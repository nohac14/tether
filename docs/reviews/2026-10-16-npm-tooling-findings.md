## Compatibility and unchanged quality gates

Five mandatory tests in `tooling/markdown-toolchain.test.mjs` verify:

- The rule engine remains 0.41.1, the same version pinned by CLI2 0.23.3
  (verified against official npm metadata). The previous settings are unchanged:
  MD013 false, MD024 siblings-only,
  MD033 false, MD036 false; all other default rules remain active.
- Actual CLI TOML loading plus Unicode/array parsing and malformed-input
  rejection by the actual overridden TOML parser.
- Actual CLI YAML loading and malformed YAML rejection.
- Ignored dependency/build fixtures excluded while invalid source Markdown
  still fails with MD041.
- Inline/block math rendered through the actual Micromark/KaTeX consumer, with
  an untrusted link rejected under `trust: false`.

These are compatibility tests, not exhaustive security proofs. The CLI probes
multiple parsers: invalid TOML may be valid YAML, so strict malformed TOML
coverage tests its real parser. Its preliminary `run-con` loader also parses
the explicit config as JSON before JSONC-aware handling; Prettier's JSONC
trailing commas break that earlier stage. Strict `.markdownlint.json` preserves
the same settings without disabling formatting or changing another dependency.

The original CLI2 ignore patterns traversed vendor/build documents. The new
CLI uses documented `--ignore-path .gitignore`; a fixture verifies source
coverage remains intact. ESLint and links exclude the dependency cache, with
a separate link-checker regression proving broken source links still fail.

There were 606 baseline Markdown findings in 32 source documents. Mechanical
table/blank-line/link/fence fixes, plus moving three existing audit titles
before execution logs, resolved them. No SPEC requirement, architecture, or
review conclusion changed. All 60 source Markdown files now pass lint/links.

Vitest originally treated the existing `node:test` scanner suite as a Vitest
suite. Root `test:unit` now requires both runners; that independently executed
Node suite alone is excluded from Vitest discovery. No test is skipped.
The scanner's executable-path comparison now uses standard `pathToFileURL`.

Renaming the config exposed another preexisting scanner bug: Git's cached file
list includes deleted worktree paths, causing ENOENT. Only paths Git explicitly
reports deleted are now excluded; unexpected read failures still fail closed.
A disposable fixture repository proves tracked/untracked scanning, redacted
fake-credential detection, and unexpected-missing-path failure. No real Git
history or permissions are modified.
